# Aurora Swapper 设计

日期：2026-09-26

给 OptiScaler Aurora 做一个 Swapper 式的 Windows 桌面程序。用它完成进游戏之前的安装、修复和还原。不合并 Aurora 源码，也不在游戏里代替 Insert 面板。

## 目标

用户在 Windows 上打开这个程序，从 Steam 库或手动添加的文件夹里选中游戏，指定本机已解压的 Aurora 发布包，然后安装、修复运行库或还原。Mac 只用来开发和用假目录测试。

第一版做完的标准：在 Windows 上对一个假游戏目录，能完成安装、修复、还原三次操作；还原失败时游戏目录里的 Aurora 文件还在；指到 `.7z` 或 Aurora 源码树时不能安装。

## 非目标

- 不编译、不修改、不内置 Aurora 的 C++ 源码。
- Aurora 发布包支持两种来源：本机指定已解压目录，或从 Aurora GitHub Release 下载并自动解压。
- 中文界面默认走国内镜像，其他语言默认走 GitHub / 官方源；下载窗口允许用户显式切换来源。
- 在线发布包必须使用 Release API 提供的 SHA-256 摘要校验，校验、解压或目录检查失败时不替换当前有效发布包。
- 不运行会提问的 `setup_windows.bat`。
- 不实现 Feeder、RenoDX、Multipass、模拟器、dgVoodoo、社区、聊天、F8 叠层。
- 不扫描 Epic、GOG、Xbox，不全盘扫描。
- 不把游戏内的 Insert 调参搬到桌面。巫师 3 那套必须进游戏保存再重启的步骤只显示文字。
- 不新做 38 种语言。

以 [DLSS 5 Swapper](https://github.com/rakanki911/DLSS5-Swapper) 2.2.7 的源码为底，保留原项目 MIT 许可并在“关于”页注明 Rakan Alkhaldi 的来源。当前 Aurora Swapper 的开发者署名为 [spikejulia](https://github.com/spikejulia)。

Aurora 上游为 [OptiScaler-Aurora](https://github.com/abc354402600/OptiScaler-Aurora)，许可为 GPL-3.0。它的发布包不放进本仓库，也不打进安装包；用户可以在设置里指定本机目录，或下载到程序自己的 `userData/aurora-packages` 缓存。关于页分别列明 Swapper 派生界面（MIT）和 Aurora 本体（GPL-3.0），并说明 Aurora 包由用户本地指定或在线下载，不随本应用分发。应用自己的 Release 发布后（v0.1.0 于 2026-11-02 发布），“关于”页的第二个按钮指向本项目发布页 `https://github.com/SpikeJulia/Aurora-Swapper/releases/latest`；应用自身的更新检查也只查本项目仓库，不查上游 Swapper 或 Aurora 的 Release。

## 运行和开发

- 成品跑在 Windows 10/11 x64。
- 在 Mac 上开发。Electron 窗口可以在 Mac 上打开。
- 调用 `runtime_sync.ps1` 只在 `process.platform === 'win32'` 时发生。
- Mac 上的测试使用临时目录，断言拷贝结果、代理 DLL 文件名，以及准备传给 PowerShell 的参数。不在 Mac 上执行 PowerShell。

## 界面

侧栏六页：游戏库、使用指南、插件、历史、设置、关于，沿用 Swapper 现有的布局和样式。聊天、社区、Overlay 不进入 Aurora 的主界面。

### 游戏库（主页与游戏页合并）

- 默认打开游戏库，不再单独维护重复的 Aurora 主页和最近游戏区。
- 标题区显示游戏总数，提供重新扫描和添加游戏菜单（单个游戏、游戏库文件夹）。
- Aurora 发布包状态条与设置页共用选择入口；未配置时仍可浏览游戏，已有记录仍可还原。
- 支持名称/目录搜索、Aurora 状态筛选及更多 API、DLSS、插件筛选；排序提供最近游玩、按库分组、名称 A–Z、名称 Z–A。
- 最近游玩仅记录通过 Aurora Swapper 成功启动的游戏，不把安装／修复／还原操作历史或 Steam 等平台直接启动记录当作游玩时间；没有记录的游戏按名称兜底，同一时间保持原有次序。
- 按库分组使用 Steam、Epic Games、GOG、Xbox、Ubisoft、手动添加、我的文件夹的既定顺序，组内按名称 A–Z；其他排序跨全部来源平铺。
- 状态来自 Aurora 安装记录：未安装、已安装、安装未完成、状态待确认；记录损坏时展示路径并禁用修改。
- 继续保留拖入游戏文件夹、来源分组、游戏详情、键盘 Enter 和右键菜单入口。

- 读取 Steam 的 `libraryfolders.vdf`，再加上手动添加的文件夹。
- 可以按名称搜索。
- 安装目标是检测到的游戏 exe 所在目录，不是 Steam 库根目录。详情页可以改这个目录。
- 已知游戏用游戏目录名和 exe 文件名做不区分大小写的包含匹配。匹配词就是下表里的中文名和英文名。对上任一词即使用该行的预选代理和说明。
- 点进一款游戏后，详情只有这些内容：
  - 状态至少显示未安装、已安装、安装未完成；记录损坏、未知记录状态或路径冲突时显示状态待确认。程序不猜测启动器是否覆盖过运行库。已安装时固定显示一句提示：若启动器验证或更新过游戏，点修复。
  - 代理 DLL 下拉。可选 `dxgi.dll`、`winmm.dll`、`version.dll`、`dbghelp.dll`、`d3d12.dll`、`wininet.dll`、`winhttp.dll`。同一款游戏同时只保留一个。
  - 安装。游戏进程在运行时按钮不可用。
  - 修复运行库。
  - 还原原始文件。
  - 打开游戏目录。
  - 已知游戏说明。只对下表里的游戏显示。

| 游戏 | 预选代理 | 说明里要写的话 |
|---|---|---|
| 异环 / Neverness to Everness | `winmm.dll` | `dxgi.dll` 可能被报非法模块。`Run inside the upscaler` 不建议开。 |
| 鬼武者：剑之道 / Onimusha | `dxgi.dll` | `Run inside the upscaler` 会花屏，保持关。 |
| 巫师 3 / The Witcher 3 | `dxgi.dll` | 游戏内超分选 DLSS，关掉原生帧生成。进游戏后 Insert：FG Input = OptiFG (Upscaler)，FG Output = DLSSG，FG Nvngx Replacement = None (Real DLSSG)。保存后完全退出再开，进场景后再开 DLSSG，选 2X–6X。 |
| 黎明行者之血 / The Blood of Dawnwalker | `dxgi.dll` | DLSS 5 和 6X 可以同时开。 |

其他游戏默认 `dxgi.dll`，不显示专用说明。

### 使用指南

- 游戏库之后增加只读指南，可离线查看；不编辑 INI、不执行安装脚本、不自动下载资料。
- 八个章节：这是什么、显卡与硬件要求、快速上手、基础设置与保存、参数说明、调参思路、游戏专项说明、常见问题与恢复。
- 首个章节面向没用过这类工具的人：用日常语言说明这是什么、能做哪三件事、明确不是什么、开始前要准备什么、以及超分／代理 DLL／INI／帧生成等名词的含义。该章节讲的是本程序本身，不随 Aurora 版本变化，默认展开。
- 第二个章节按显卡系列说明能拿到什么功能：NVIDIA 分 RTX 50／40／30／20／GTX，AMD 分 RX 9000／7000／6000／5000，Intel Arc 另列；另附「比显卡型号更容易卡住人的四条」——游戏要有超分输入、渲染 API 在支持范围内、驱动版本要对、一个游戏只能有一个代理。显卡能力属上游版本事实，因此独立成章而不并入讲本程序的首章。
- 空游戏库给出「第一次用？先看这是什么」的入口，让新用户先读到说明再加游戏。
- 支持中英文跨语言关键词／参数名搜索；章节和参数卡可折叠，搜索结果自动展开，清空搜索恢复浏览时的折叠状态。
- 参数条目说明作用、取值／起始设置、适用条件、生效与重启、恢复方法；可复制英文参数名，正文可选中复制。
- 首版 51 条说明，常用参数分组解释；完整高级参数通过明确点击的上游 INI 链接查阅，不将未经确认的默认值或兼容性当作结论。
- 操作步骤写到可照做的粒度：快速上手每步写明在本程序里点哪里、成功长什么样；另设「本程序里每个按钮做什么」；基础设置给出用任务管理器定位游戏 EXE 目录的做法；调参思路给出一条「一次只改一项」的实测流程；常见问题补充与其它 Mod Loader 抢占同一个代理名的情形。
- 内容基于 `aurora-v1.1.2` 的固定提交 `1d22875d05fac2d7ffb86ed912b943ce1a6e915a`，核对日期 2026-11-02；给出版本一致／不同、本地版本未知、发布包缺失／无效、记录无法读取等提示。下载新包不会静默改写离线指南。
- 显卡章节的能力判断同时引用 NVIDIA 官方 GeForce 对比表、AMD 官方 FSR 硬件兼容表，以及 Aurora v1.1.2 锁定的上游文档；两者口径不一致时（FSR4 在 RX 6000 上的覆盖）两个口径都写明，不挑一个当定论。
- 安装说明以本程序的安装、修复和还原入口为准，不让用户额外运行 `setup_windows.bat`。标明历史实测与实验功能的边界，包含反作弊风险、日志隐私和备份保护说明。
- 底部保留 Aurora／OptiScaler／社区来源署名、上游 GPL-3.0 说明，以及固定版本的安装指南、INI 和兼容性白名单链接。

## 发布包是否有效

设置里的路径同时满足下面三条才算有效，否则安装和修复不可用，并在设置页说明原因。在线下载的压缩包解压到缓存后也必须通过同样的校验：

- 是一个已解压的目录，不是 `.7z` 或其他压缩包。
- 目录里能找到 `OptiScaler.dll` 和 `runtime_sync.ps1`。
- 目录里没有 `OptiScaler.sln`。有它说明指到了源码树，不是发布包。

`Check_DLSS_Runtime.bat` 可以随发布包一起拷贝，但程序不依赖它。修复直接调用 `runtime_sync.ps1 -Mode Check`。本程序安装与修复只调用 `runtime_sync.ps1`，不会运行 `setup_windows.bat`。

## 安装

安装前：

- 发布包必须有效。
- 游戏 exe 目录必须已确定。
- 该游戏的进程没有在运行。Windows 上按 exe 文件名检查。查不到时仍允许安装，但详情页提示未能确认游戏已关闭。
- 若目标代理 DLL 已存在，且不是本程序上次安装留下的文件，先询问是否覆盖。用户拒绝则中止，不改目录。

安装动作，按顺序，任何一步失败就停止：

1. 把本次将要覆盖或新增的路径记入该游戏的安装记录。记录写在程序自己的数据目录，不写进游戏目录。
2. 将发布包中的文件拷进游戏 exe 目录，跳过 `OptiScaler.sln`。`OptiScaler.dll` 先不拷成这个名字。
3. 在游戏目录把这份 DLL 落成用户选中的代理名。若本程序上次安装了另一个代理名，只删除记录里的那一个旧代理，不删除来源不明的同名 DLL。
4. 仅在 Windows 上执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "<游戏目录>\runtime_sync.ps1" -Mode Install -InstallDir "<游戏目录>"
```

5. 退出码为 0 后，再拷贝未发生重名冲突的插件。插件拷贝失败不撤回 Aurora，状态仍为已安装，历史里记下插件失败。
6. Aurora 安装成功后写入历史。状态变为已安装。

拷贝或改名失败：按安装记录撤回这一次已经写入的文件，不调用 `Install`。已有备份按记录放回。

`Install` 退出码非 0：不撤回已经拷入的文件，不拷插件。状态为「安装未完成」，详情页展示脚本输出，并提供还原。

## 修复

仅当状态是已安装或安装未完成，且发布包仍然有效时可用。游戏进程在运行时不可用。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "<游戏目录>\runtime_sync.ps1" -Mode Check -InstallDir "<游戏目录>"
```

退出码非 0 只展示输出，不删除文件。退出码为 0 则把状态更新为已安装。

## 还原

游戏进程在运行时不可用。

1. 游戏目录里有 `runtime_sync.ps1` 时，执行 `-Mode Restore`。退出码非 0：停止。不删除任何文件。历史记为还原失败。
2. 没有 `runtime_sync.ps1`，但游戏目录里仍有 `OptiScaler\RuntimeSync`：停止，不删除任何文件。详情页说明要先放回 `runtime_sync.ps1` 再还原。
3. 只有 Restore 退出码为 0，或两者都不存在时，才删除该游戏安装记录里列出的文件。记录之外的文件不动。
4. 第 3 步完成后，清除该游戏的安装记录，状态变为未安装，写入历史。

## 可靠性补充（2026-09-29）

- 在修改游戏目录前，先把每次操作的事务检查点和本次写入前快照持久化到 `userData`；复制阶段失败时按快照回滚，脚本阶段中断时保留记录供恢复，不覆盖长期原始备份。
- 切换代理时，先按旧记录恢复被替换的原始 DLL；只移除本工具此前新增的旧代理，不删除来源不明的文件。
- 详情页与右键菜单共用同一 Aurora 操作入口；主进程按游戏串行化操作并检查进程状态，未知状态明确提示而不伪装为已确认关闭。
- 安装记录、事务、长期备份与操作历史保存在 Electron `userData` 中。记录损坏时禁止变更，报告文件路径并保留原文件。
- 读取已保存的安装记录或事务后，先验证所有目标都在所选游戏目录内，长期备份都在该游戏的 Aurora 备份根内，事务快照都在其对应事务目录内；发现路径穿越、符号链接或别名冲突时停止自动修改与清理。
- 卸载程序不自动还原游戏文件，也不删除上述应用数据；卸载前应在应用内逐款执行“还原原始文件”。

## 测试

Mac 上用 Node 测试 Aurora 安装模块，不启动 Electron，也不调用 PowerShell：

- 有效目录、`.7z`、含 `OptiScaler.sln` 的目录，三种校验结果。
- 拷贝后游戏目录里只有一个代理 DLL，名字与选择一致。
- 更换代理时，只去掉记录中的旧代理。
- 目标代理已存在且不在记录中时，不覆盖，除非测试显式传入确认。
- 拷贝中途失败会撤回已写入的文件。
- 插件重名被拒绝，Aurora 文件保持不变。
- 三种模式生成的 PowerShell 参数分别是 `Install`、`Check`、`Restore`，且 `-InstallDir` 是游戏 exe 目录。
- `Restore` 被设定为失败时，记录中的文件仍在。
- 没有 `runtime_sync.ps1` 但存在 `OptiScaler/RuntimeSync` 时，不删除记录中的文件。

Windows 上的人工检查不纳入自动测试：用一个含假 exe 的目录和一份最小发布包（含 `OptiScaler.dll` 与一个只打印参数就退出的 `runtime_sync.ps1`）走一遍安装、修复、还原。真 Aurora 包和真游戏由用户在自己的 Windows 机器上试。
